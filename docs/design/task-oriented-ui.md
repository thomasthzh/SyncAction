# 以任务和对象组织侧栏

日期：2026-10-23。适用范围：后续渐进界面改进。保持现有品牌、同步可靠性与权限边界，按用户当前任务重新判断信息和动作的位置。

## 产品规则

1. **先认出对象，再执行动作。**
   房间内先回答正在看什么、谁领播、自己是否跟随；打开页面、跟随播放与只对齐此刻是不同动作，文案准确表达后果。
2. **已确认的上下文由系统携带。**
   登录、批准和网站同意后继续原任务；房间、服务器或页面改变时作废旧意图，不要求用户重复找目标，也不在新对象上执行迟到动作。
3. **常用事实和动作在第一层。**
   关键身份、当前对象和下一步直接可达；历史、低频配置与异常恢复各有明确位置。减少嵌套不等于把全部内容纵向堆在同一页。
4. **同一事实共享一个来源。**
   页面、成员和播放组可以互相定位，界面不要各自维护另一套状态；关闭详情返回原位置，刷新不抢走焦点和正在阅读的对象。
5. **状态说明作用域。**
   房间状态不代表媒体已跟随，分享完成不代表已授权播放。等待、待确认、明确失败、成功分别按真实结果展示。
6. **正常路径简明，失败能够继续。**
   就近显示可理解的原因和恢复动作，保留可恢复输入；重要操作等待真实确认，不虚构撤销或将超时直接当失败。
7. **形式随任务变化。**
   页面用可扫描列表，播放协作用状态与控制，成员表达身份和位置；容器数量和卡片面积不代表内容清楚。
8. **材质和动效帮助理解。**
   保留玻璃语言，重点是内容稳定、层级可辨、文字可读；动画用于状态连续性和反馈，尊重减少动态效果 / 透明度及强制颜色，避免反复播放整页入场。

这些是可测试的设计约束，不是统一配色、字号或技术栈模板。当前没有真人计时与大样本证据，不宣称效率提升百分比。

## 第一批具体改变

- 播放组中的“跳转并同步”改为“打开领播页面”，继续只打开页面，不隐式加入播放组或对齐媒体进度。
- 房间健康状态注明“房间已同步”，与媒体自身的授权和跟随状态分开。在线人数在房间标题保留一次，摘要栏保留连接、页面、播放组三项。
- 无共享页时保留标题、数量与简短空状态；初次观看的突出指引由“开始一起看”承担。底部独立分享操作仍可用。

此批不改变同步协议、业务命令、权限同意、原目标续接或媒体生命周期；不是对全部侧栏的重构完成声明。

## 观看工作面、授权与连接

第二批把设计约束应用到实际布局与操作：

- 观看区域只呈现一个主要播放组，优先选择本人参与的组，再选择推荐组。页面、领播者、媒体进度和本人设备的参与状态在同一工作面；切换查看不发出加入或对齐命令，房间更新不重置选择和焦点。
- 本设备领播、本设备参与跟随、由另一设备参与、尚未加入、媒体降级和离线分别表达。组成员身份不等于视频正在播放，服务在线也不等于房间或媒体已同步。
- 关闭播放组进入就近的管理展开区；加入、对齐一次和打开领播页面直接可达。领播者查看其他组时，自己组的待处理提议仍可决策。
- 第一次观看按共享页面、网站许可、创建播放组三个真实阶段呈现。授权窗首先说明允许后继续哪项操作及网站范围；数据说明和本人同意保持可见，浏览器匹配模式和条款版本按需展开。取消、失败重试与上下文失效沿用同一协调流程。
- 返回大厅时优先呈现已有房间。健康服务状态收成可展开的一行；异常的原因与恢复按钮保持可见，检测服务和重新连接服务器分别执行对应操作。
- 玻璃保留在浮动控制层，观看内容使用稳定、不采样背景的内容面。切换播放组只让局部内容进入，状态变色维持连续；媒体更新不反复播放入场。减少动画、透明度与强制颜色有对应呈现。

样式按观看工作面、连接与授权拆分，继续复用现有业务命令与状态来源。玻璃折射图仅在边缘计算距离与法线，保持原像素输出；性能数据的范围是生成函数或浏览器局部采样，不代表整机容量或真人操作效率。

## 后续顺序与检查

| 方向           | 要解决的问题                                             | 验证                                               |
| -------------- | -------------------------------------------------------- | -------------------------------------------------- |
| 首次与再次进入 | 配置 / 待批准 / 登录入口表达一致；有房间时优先继续原协作 | 不提示按钮名的任务观察、原目标续接及上下文失效回归 |
| 观看工作面     | 当前视频、领播者、本人跟随角色和下一步在同一面上清楚可见 | 双人播放与切页，长标题、多人、多组、键盘返回       |
| 授权与恢复     | 明确允许后继续什么；健康技术指标按需查看，异常就近恢复   | 取消、失败、未知结果、换服务器 / 房间 / 页面       |
| 材质与动效     | 层级与焦点连续，内容可读且不增加等待                     | 320 / 420px、缩放、减少动效、代表性设备采样        |

每批记录改动前事实、用户后果、实现、验证与未覆盖范围。截图、自动化、代码审查和真人理解测试各有作用，不互相替代。

## 统一控制台工作区 · 2026-10-25

扩展与管理员端共享任务、对象、状态和动作的组织规则，分别服务共同浏览与服务管理。

- 侧栏保持有限高度，导航和当前页工具栏可见；观看、页面、成员各自滚动并保留上下文。工作区切换不发业务命令，既不更换房间，也不改变媒体参与关系。待处理提议在其他工作区仍有返回入口。
- 大厅的已有房间与公开目录分开浏览。正常服务检测只在设置中按需进行，未配置的占位地址不做探测；实际连接错误仍就近显示原因与恢复动作。设置子页面关闭后回到设置，提交中不允许跳去另一个任务。
- 成员打开操作依据该成员实际设备的页面绑定判断，不能用“某个成员可跳转”代表所有人可跳转。状态未到达时显示待同步，不推断离线。
- 管理端保持七个工作区，以审批、密钥、房间、账户对象为主要内容；容量和数据库读取事实作辅助信息。窄屏使用字段明确的对象行，让动作紧邻对象。
- 管理员页面的纯呈现与 DOM 构造独立成模块，异步请求、命令、权威刷新、失效与焦点协调保持集中。保留单次密钥生命周期、提交锁、服务端确认及失败恢复。
- 密集关系使用共同白色内容面，玻璃集中在控制层。动画仅作用于局部变化，不重播整页入场；减少动态、透明度及系统强制颜色均有对应路径。

验证分为视觉数据夹具、真实隔离后端双端协作、管理员真实写入与回归测试。媒体宿主权限预先授予的自动化段只验证应用内说明与同意流程，不代表原生浏览器权限提示已验收；扩展文档作为标签页打开的检查也不替代原生侧栏容器或真人理解测试。
