# 以任务和对象组织侧栏

日期：2026-10-23。适用范围：后续渐进界面改进。保持现有品牌、同步可靠性与权限边界，按用户当前任务重新判断信息和动作的位置。

## 产品规则

1. **先认出对象，再执行动作。**
   房间内先回答正在看什么、谁领播、自己是否跟随；打开页面、跟随播放与只对齐此刻是不同动作，文案准确表达后果。
2. **已确认的上下文由系统携带。**
   登录、批准和网站同意后继续原任务；房间、服务器或页面改变时作废旧意图，不要求用户重复找目标，也不在新对象上执行迟到动作。
3. **常用事实和动作在第一层。**
   关键身份、当前对象和下一步直接可达；历史、低频配置与异常恢复各有明确位置。减少嵌套不等于把全部内容纵向堆在同一页。
4. **同一事实共享一个来源。**
   页面、成员和播放组可以互相定位，界面不要各自维护另一套状态；关闭详情返回原位置，刷新不抢走焦点和正在阅读的对象。
5. **状态说明作用域。**
   房间状态不代表媒体已跟随，分享完成不代表已授权播放。等待、待确认、明确失败、成功分别按真实结果展示。
6. **正常路径简明，失败能够继续。**
   就近显示可理解的原因和恢复动作，保留可恢复输入；重要操作等待真实确认，不虚构撤销或将超时直接当失败。
7. **形式随任务变化。**
   页面用可扫描列表，播放协作用状态与控制，成员表达身份和位置；容器数量和卡片面积不代表内容清楚。
8. **材质和动效帮助理解。**
   保留玻璃语言，重点是内容稳定、层级可辨、文字可读；动画用于状态连续性和反馈，尊重减少动态效果 / 透明度及强制颜色，避免反复播放整页入场。

这些是可测试的设计约束，不是统一配色、字号或技术栈模板。当前没有真人计时与大样本证据，不宣称效率提升百分比。

## 第一批具体改变

- 播放组中的“跳转并同步”改为“打开领播页面”，继续只打开页面，不隐式加入播放组或对齐媒体进度。
- 房间健康状态注明“房间已同步”，与媒体自身的授权和跟随状态分开。在线人数在房间标题保留一次，摘要栏保留连接、页面、播放组三项。
- 无共享页时保留标题、数量与简短空状态；初次观看的突出指引由“开始一起看”承担。底部独立分享操作仍可用。

此批不改变同步协议、业务命令、权限同意、原目标续接或媒体生命周期；不是对全部侧栏的重构完成声明。

## 后续顺序与检查

| 方向           | 要解决的问题                                             | 验证                                               |
| -------------- | -------------------------------------------------------- | -------------------------------------------------- |
| 首次与再次进入 | 配置 / 待批准 / 登录入口表达一致；有房间时优先继续原协作 | 不提示按钮名的任务观察、原目标续接及上下文失效回归 |
| 观看工作面     | 当前视频、领播者、本人跟随角色和下一步在同一面上清楚可见 | 双人播放与切页，长标题、多人、多组、键盘返回       |
| 授权与恢复     | 明确允许后继续什么；健康技术指标按需查看，异常就近恢复   | 取消、失败、未知结果、换服务器 / 房间 / 页面       |
| 材质与动效     | 层级与焦点连续，内容可读且不增加等待                     | 320 / 420px、缩放、减少动效、代表性设备采样        |

每批记录改动前事实、用户后果、实现、验证与未覆盖范围。截图、自动化、代码审查和真人理解测试各有作用，不互相替代。
